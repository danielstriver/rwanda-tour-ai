## Commands

```bash
npm run dev              # Start Vite dev server (frontend only, no API)
npx vercel dev           # Start full-stack dev with Vercel serverless functions (requires .env)
npm run build            # TypeScript compile + Vite production build
npm run preview          # Preview production build locally
npm run sync-supabase    # Sync knowledge base to Supabase vector DB

# Data pipeline scripts (run with tsx)
npx tsx scripts/generateEmbeddings.ts   # Regenerate embeddings after updating knowledge base
npx tsx scripts/buildKnowledgeBase.ts   # Rebuild knowledge base from source data
npx tsx scripts/testChat.ts             # CLI test for RAG retrieval and LLM logic
```

No lint or test commands are configured.

## Environment Variables

Required in `.env`:
- `HUGGINGFACE_API_KEY` — used by both API routes for LLM and embedding inference
- `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` — vector DB for semantic search
- `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` — rate limiting (optional; skipped if absent)

## Architecture

**RAG-powered tourism assistant for Rwanda.** Users select preferences, get static recommendations, then chat with an AI that answers from a curated knowledge base.

### Page navigation model

`RwandaTourPage.tsx` controls three mutually exclusive views via two booleans (`isExploring`, `isHowItWorks`). Both default to `false`, showing the landing page. Setting `isExploring = true` switches to the full-screen chat (`AIChatSection`); the navbar/footer are hidden in this mode. `PreferenceProvider` wraps the whole page so preferences are accessible in both the recommendation and chat sections.

### Request flow (AI chat)

1. User message → `api/chat.ts` (Vercel serverless)
2. Rate limit check via Upstash Redis (10 req/24h per IP; bypassed when env vars absent)
3. Input validated with Zod (`ChatPayloadSchema`)
4. Query embedded via `sentence-transformers/all-MiniLM-L6-v2` (Hugging Face)
5. Top-3 matches retrieved from Supabase via `match_destinations` RPC (pgvector, threshold 0.5)
6. Context injected into system prompt → raw-text streamed response from `Qwen/Qwen2.5-72B-Instruct`
7. Session title auto-generated by `api/title.ts` from the first user message

The streaming response is plain text chunks written directly to the response — not SSE JSON envelopes.

### Data layer

- `src/data/rwanda_knowledge.json` — source of truth for destinations/experiences
- `src/data/rwanda_embeddings.json` — pre-computed vector representations
- Supabase (PostgreSQL + pgvector) — vector similarity search at query time via `match_destinations` RPC
- `scripts/syncToSupabase.ts` — uploads knowledge base to Supabase

### Frontend structure

- `src/pages/RwandaTourPage.tsx` — top-level page orchestrating all sections and view-switching
- `src/features/` — domain modules: `ai/`, `preferences/`, `recommendations/`
- `src/features/preferences/PreferenceContext.tsx` — only shared state in the app (experience, budget, duration)
- `src/components/` — shared presentational components
- `src/hooks/useLanguage.tsx` — i18n for EN/FR/Kinyarwanda; all translations live in this file as a flat dot-notation key map (e.g. `'hero.title.part1'`). Never add a translation key anywhere else.
- `src/types/` — shared TypeScript interfaces (`chat.ts`, `knowledge.ts`, `recommendation.ts`)
- `src/utils/constants.ts` — experience types, budget tiers, durations, sample recommendations

Chat sessions (`ChatSession[]`) are persisted in `localStorage` under the key `rwanda_tour_chat_sessions`.

## Coding Conventions

- Strict TypeScript — no `any`
- All UI via Chakra UI primitives and `semanticTokens` (supports dark mode)
- Animations via Framer Motion only; icons via Lucide React only
- Components: `PascalCase`; hooks: `useCamelCase`; utilities/variables: `camelCase`
- Keep UI state local; only lift to shared state when clearly required (`PreferenceContext` is the only current example)
- Prefer small reusable components over large page-level implementations
- Use `useLanguage` hook for all user-facing strings — add new keys to the translations map in `useLanguage.tsx`, never hardcode language-specific text
- New backend work targets Vercel Functions; do not introduce a separate server
- Use conventional commit messages; keep commits focused (no mixing refactors with features)
